# ☁ MCSync · Minecraft 存档云同步工具

一套「Linux 服务端 + Windows 客户端」的 Minecraft 存档云同步方案：自动识别 PCL2 / HMCL / 官方 / Prism / MultiMC / Modrinth 的实例与存档，按 4 MiB 内容寻址分块做增量同步，带版本快照、冲突处理与 Web 管理页。

## 零之二、整合包配置同步

存档之外，实例的 `config/` 目录也可以单独同步 —— 里面放着模组与服务端配置。
多人玩同一个整合包时，只有配置也一起同步，各人的世界表现才不会跑偏。

- 本地页选中实例后点「⚙ 同步整合包配置」上传
- 云端列表里带 `⚙ 整合包配置` 标记，选中后下载会装到本机同名实例的 `config/`
- 不同整合包的配置各自独立，互不覆盖
- 客户端自身配置（不属实例）不参与同步

## 零之三、账号与权限

服务端采用**账号登录 + 两级权限**，客户端不再用服务器随机口令连接。

| 角色 | 客户端 | 管理面板 |
|---|---|---|
| 管理员 | 完整功能 | 全部权限：管理云端存档（删/回滚/改名/归类/清理）+ 账号管理 |
| 普通用户 | 完整功能（上传/下载/版本管理） | 只读浏览 |

**没有自助注册**——账号只能由管理员在面板「账号管理」里创建，
拿到服务器地址的人无法自行进站。

**首次使用流程**：

1. `sudo bash deploy.sh`，记下输出的 **管理员密钥**（16 位）
2. 浏览器打开管理页，用这串密钥**创建第一个管理员账号**
3. 之后一律用账号登录；在「账号管理」里给其他使用者开号
4. Windows 客户端「设置」里填 **账号 + 口令** 连接

口令用 PBKDF2-HMAC-SHA256 加盐存储（20 万次迭代），不存明文。
管理员停用或删除账号后，该账号下所有设备**立即失效**。
最后一个管理员不可被降级或删除，避免系统失去管理能力。

```
server/accounts.py    # 账号存储与口令哈希
server/auth.py        # 鉴权：账号 → 会话 / 客户端私钥签名
```

## 零之四、界面语言

设置 → 外观里可切换 **简体中文 / English**，重启客户端后完全生效。

实现要点：源码里的字符串本身就是中文，所以中文模式原样返回、无需维护词条；
英文模式查表，未翻译的自动退回中文（不会出现空白或占位符）。
新增界面文案时只需往 `client/core/i18n.py` 的 `_EN` 里加一条。

## 零之五、登录与设计规范

**登录**：打开软件第一屏就是登录窗口（不是藏在设置里）。
可勾选「记住口令，下次自动登录」。口令存于系统加密区（Windows 走 DPAPI），
配置文件里不留明文。不登录也能管理本地存档，只是云同步不可用。

**设计规范**：界面数值全部来自 `client/ui/design.py` 的设计令牌——
间距只能用 4/8/12/16/24/32，字号分 H1/H2/正文/次要/说明五档，
圆角与尺寸同样走刻度。改一处即可全局生效，不会再出现随手填数值导致的版面松散。
配色对比度按 WCAG AA 校验（正文 ≥4.5:1）。

**启动性能**：实例列表先秒出（只读 level.dat），体积后台补；
重扫结果与现有列表一致时不重建界面，避免连锁重新加载。

## 零之六、区块清理（按 InhabitedTime）

侧栏「🧹 区块清理」页可以按**玩家在区块内的累计停留时间**筛选并删除区块，
用来清掉"生成了但没人待过"的探索痕迹，给存档瘦身。

**默认阈值 = 停留不足 1 秒**（`InhabitedTime < 20 tick`）。这个条件非常保守：
只有刚生成就离开的区块会命中，基本不会误删有建筑、箱子或下界传送门的区域。
阈值可在页面上调整（秒）。

### 安全设计

| 机制 | 说明 |
|---|---|
| 默认只预览 | 点「扫描预览」**一个字节都不改**，只出报告：命中区块数、按维度分布、涉及文件、预计释放空间 |
| 二次确认 | 看过报告后点「执行清理」，还要再过一次确认弹窗 |
| 强制备份 | 执行前自动把整个存档硬链接备份到 `_MCSyncBackups/` |
| 游戏关闭检查 | 检测到 `session.lock` 被占用会拦截，避免读到写入中的区块 |
| 三目录协同 | `region/` / `entities/` / `poi/` 按同一全局区块坐标一起清理，不留孤立实体与 POI |
| 多维度 | 主世界、下界、末地、自定义维度分别列出，可单独勾选 |
| 多整合包 | 顶部「游戏实例」下拉切换即可处理其他整合包，每个实例独立列出自己的存档 |
| 云端可回滚 | 清理的是本地文件；云端历史版本仍在，必要时从版本管理回滚 |

### 与 MCA Selector 对齐的实现细节

参考了开源项目 [Querz/mcaselector](https://github.com/Querz/mcaselector)
（`io/WorldDirectories.java`、`io/mca/CompressionType.java`、`io/mca/MCAFile.java`）：

- **世界目录检测**：只要找到 `region` 文件夹就当作一个可处理世界，
  `poi` / `entities` 可选；不对整合包或维度名做白名单。因此经典
  `region` / `DIM-1` / `DIM1`、1.16+ 的 `dimensions/<ns>/<name>/region`、
  以及 26.1 的 `dimensions/minecraft/overworld|the_nether|the_end/region`
  都会被递归识别，自定义维度也照常列出。
- **压缩类型字节**：`NONE 0` / `GZIP 1` / `ZLIB 2` / `UNCOMPRESSED 3` / `LZ4 4`；
  最高位（Java 里是负 byte）表示 chunk 数据放在外部 `.mcc` 文件，低 7 位仍是
  上述算法。四种常规压缩都能读出 `InhabitedTime`。
- **能力检测**会遍历**所有维度**并只抽样 `.mca` 文件。旧版只取目录列表前 8 项、
  且第一个维度样本够了就提前退出：`region` 目录里混着 `.mcc` 时一个区块都读不到，
  整个存档被误判成「不支持」——表现就是「多个整合包只有一个能清理」。已修复。
- **外部 `.mcc` 标记**的 region 整份不参与清理，但原始扇区字节完整保留，
  绝不因为读不懂就丢掉玩家数据。

### 低版本存档自动禁用

`InhabitedTime` 不是所有版本都写。若整个存档**一个区块都读不到该字段**，
页面会直接禁用扫描与执行，并说明原因 —— 绝不把"没有字段"当成"没人来过"。

1.17 及以前把该字段放在 `Level.InhabitedTime`，工具同样能识别。

### 无法判定的区块一律保留

以下情况会**跳过并保留**，报告里单独列出数量，绝不删除：

- 压缩算法不认识（LZ4 / 自定义 ID 127 / 外部 `.mcc` 存储）
- NBT 损坏、长度头截断、数据越界
- 字段缺失

> 若存档使用 LZ4 压缩（部分服务端配置），安装 `lz4` 包后可正常识别；
> 未安装时这些区块会被安全保留，不影响其余区块清理。

### 清理后

文件会被**紧凑化重写**（清表项 + 回收数据区空隙），空 region 文件直接删除，
体积真的会变小。记得把清理后的存档**上传到云端**，其他人下载时才会拿到新版本。
region 内部差分已适配：改动只会让少量分片失效，重传量很小。

⚠ 删除后地形会按世界种子重新生成，边界处可能与周围生物群系不连续。
阈值只是"是否有人用过"的参考线索，不是安全判据 —— 建议先备份、先看预览地图范围，
下界尤其谨慎（传送门、要塞常常停留时间很短但很重要）。

## 零之七、共享玩家数据（不用装模组）

**解决那个经典坑**：房主把单人存档共享给别人，接手者打开世界会变成房主的
背包、位置、经验和进度，甚至把自己的角色数据覆盖掉。

原因是 Java 版 26.1 之前，单人世界把「世界所有者」的完整玩家数据额外存在
`level.dat → Data → Player`，单人模式无条件优先读它，**完全不看当前玩家 UUID**
（Mojira MC-697）。26.1 起换成 `singleplayer_uuid` 指针，数据统一放
`players/data/<UUID>.dat`，但指针仍可能指向房主。

MCSync 在**客户端侧直接改存档文件**，不用为 Forge / Fabric / NeoForge
和每个 MC 版本分别编译模组：

| 步骤 | 行为 |
|---|---|
| 归档 | 把 `Data.Player` 写成独立的 `playerdata/<原主人UUID>.dat` —— 房主再打开时按自己 UUID 就能读回来，**数据不丢** |
| 摘除 | 从 `level.dat` 删掉 `Data.Player`（26.1+ 则删掉 `singleplayer_uuid`） |
| 结果 | 游戏退回按各自 UUID 读取玩家数据：A 读 A 的，B 读 B 的，没有就新角色进世界 |

**最大的好处是不需要知道当前玩家是谁**。模组要在游戏进程里拿登录 UUID，
独立程序拿不到；而「归档 + 摘除」对房主和接手者都成立，所以零配置即可工作。

### 用法：上传时自动完成，不需要手动操作

**默认开启**：每次「上传」前自动执行归档+摘除，所以**云端版本天生就是共享友好的**，
别人下载后直接是自己的角色。不需要任何人去点修复按钮。

- 设置 → 同步 → 「上传前自动摘除房主玩家数据」可关闭（关闭后上传/下载都原样）。
- 下载时保留一层**兜底**：若云端是历史版本、仍带着内嵌房主数据，下载后自动修一次
  （幂等，正常情况不会触发）。
- **🪪 玩家数据页**只保留必要内容：自动处理状态、「我的 UUID」、处理结果输出，
  以及**对已经上传到云端的存档做补修**——选中云端存档 → 二次确认 →
  拉取最新版本 → 修正 → 上传为新版本。原版本保留可回滚，其他人重新下载即可。
- **我的 UUID（可选）**：填上后，若内嵌数据本就属于你则原样保留不动；
  留空时一律归档+摘除（房主数据会被归档回来，同样不丢）。

### 安全设计

- 改前把原始 `level.dat` 备份到 `<存档>/.mcsync/playerdata_backup/`
  （该目录默认不参与同步），同内容备份自动去重，最多保留 8 份
- 临时文件 + `os.replace` 原子写回，不会写出半截 `level.dat`
- 用保类型 NBT 读写器，12 种 TAG（含空 List 的元素类型、IntArray/LongArray）
  语义级完整保留，`level.dat` 其余字段一个不动
- 读不出原主人 UUID 时，**不伪装成任何玩家的数据文件**，而是把整份内嵌数据
  另存到 `.mcsync` 备份区，绝不丢数据也绝不顶掉别人的角色
- 目标 `.dat` 已存在且是真实数据时保留；只有「空壳」才备份成
  `.spd_backup` 后覆盖（该后缀已被默认忽略规则排除）
- `level.dat_old` 一并摘除，避免恢复流程把它读回去
- 游戏运行中（`session.lock` 被占用）拒绝修改
- **完全幂等**：第二次运行检测不到内嵌数据，直接跳过，不会来回震荡

### 多人协作时的流转

A 上传（自动摘除 + 归档）→ 云端版本已是共享友好 → B 下载直接是自己的角色，
且 B 也拿到 A 那份归档数据（按各自 UUID 读取，互不覆盖）→ B 玩完再上传同理。

> 旧版本上传的存档若还带着房主数据，用「🪪 玩家数据 → ☁ 处理云端存档」
> 补修一次即可；在那之前别人下载时也会走兜底自动修（结果相同、幂等）。

⚠ 26.1+ 的存档目录结构变了（`players/data`），核心同步模式已把 `players/`
纳入范围；旧版 `playerdata/` 照常支持。

## 零、推送到 GitHub

仓库内已提供一键脚本，双击 `push.bat` 即可：

```bat
push.bat                     :: 交互确认后提交并推送
push.bat -m "修复某问题"      :: 指定提交信息
push.bat --dry-run           :: 只做检查，不提交不推送
push.bat -y                  :: 跳过确认直接推送
push.bat -f                  :: 首次推送就强制覆盖远端
push.bat --no-force          :: 被拒绝时不自动覆盖，改为提示手动处理
```

**默认行为**：远端若有本地没有的提交（例如新建仓库时 GitHub 自动生成的 README），
脚本会**自动用本地覆盖**，并以 `--force-with-lease` 优先（比 `--force` 安全，
能防止误覆盖别人在这期间推上去的新提交）。单人维护场景这是最省事的选择。
若仓库变为多人协作，请加 `--no-force` 关掉这个行为。

脚本会在提交前做**安全扫描**，命中的文件一律拦下（口令、私钥、用户存档、
编译产物、数据库）。`.gitignore` 已排除同类文件，扫描是第二道闸。

```
├── push.bat                 # 一键推送（Windows）
├── push.py                  # 推送逻辑（含安全扫描）
├── .gitignore               # 忽略规则
├── .gitattributes           # 行尾规则（.bat 强制 CRLF / .sh 强制 LF）
└── LICENSE                  # GPLv3 全文
```

## 二、服务端一键部署（Linux）

把整个 `mcsync` 目录传到服务器（或 `git clone`），然后：

```bash
cd mcsync/server
sudo bash deploy.sh
```

脚本会自动检测：有 Docker 就走 **Docker Compose**，没有就走 **Python venv + systemd**。

### 常用参数

| 参数 | 说明 |
|---|---|
| `--mode docker` / `--mode native` | 强制指定部署方式 |
| `-p, --port 9000` | 改监听端口（默认 8650） |
| `-d, --dir /opt/mcsync` | 改安装目录（数据在其下的 `data/`） |
| `-k, --keep 10` | 每个存档最多保留 10 个版本（0 = 不限制） |
| `--verify` | 服务端校验上传块的哈希（更安全，但更耗 CPU） |
| `--status` | 查看运行状态与健康检查 |
| `--uninstall [--purge]` | 卸载服务（`--purge` 连数据一起删） |

### 部署后的常用命令

```bash
# Docker 模式
cd /opt/mcsync && docker compose logs -f && docker compose restart

# 原生模式
journalctl -u mcsync -f
systemctl restart mcsync
```

浏览器打开 `http://服务器IP:8650` 即可进入 **Web 管理页**：查看存档与版本、下载整包 zip、回滚、删除版本。

> 云服务器记得在安全组放行端口；生产环境建议用 Nginx 反代 + HTTPS。

---

部署完成后会**直接打印 16 位配对口令**（醒目框展示），客户端和管理页都用它：

```
════════════════════════════════════════════════════
  管理员密钥（16 位）
════════════════════════════════════════════════════

        qSFEA3MR5ZTQ2nY3

  用途：浏览器打开管理页 → 用它创建第一个管理员账号
  之后：客户端一律用「账号 + 口令」登录，不再用这串
```

## 三、客户端一键构建（Windows）

1. 安装 Python 3.9 ~ 3.12（安装时勾选 **Add Python to PATH**）
2. 双击或在命令行执行：

```bat
cd mcsync\client
build.bat
```

脚本会自动：创建 `.buildenv` 虚拟环境 → 安装依赖与 PyInstaller → 生成图标 → 打包 → 输出 `dist\MCSync.exe`。

| 参数 | 说明 |
|---|---|
| `--dir` | 打包为文件夹模式（启动更快，不是单文件） |
| `--no-venv` | 直接用系统 Python，不建虚拟环境 |
| `--console` | 保留控制台窗口（排查问题用） |

体积参考：单文件约 25 ~ 40 MB。首次启动会解压临时文件，稍慢属正常；若杀软误报，把 `dist` 加入白名单。

## 四、使用流程

1. **填服务器地址**：顶部输入 `http://服务器IP:8650`，点「连接测试」，状态灯变绿即可。
2. **选实例**：左侧自动列出识别到的游戏实例；没识别到就点 **➕** 手动指定 PCL2 / HMCL 所在目录。
3. **选存档**：中间列出该实例下所有存档（显示世界名、版本、模式、难度、大小、最后游玩时间、是否已同步）。
4. **上传**：选中存档 → 「⬆ 上传到云端」。
5. **下载**：右侧选中云端存档 → 「⬇ 下载到本地」（可指定实例，没有同名存档时会新建）。
6. **版本管理**：右侧「版本管理」可查看全部快照，随时下载任意旧版本、一键回滚或删除。

底部传输面板实时显示阶段、进度条、当前文件、已传/总量、速率与剩余时间；「日志」按钮可展开详细记录。

## 五、它是怎么省带宽的

| 机制 | 说明 |
|---|---|
| **两级哈希预筛** | 先比「文件大小 + 修改时间（毫秒）」，一致就直接复用上次算好的哈希，不读盘；需要时才用 xxHash（比 SHA256 快一个量级）计算 |
| **4 MiB 内容寻址分块** | 文件被切成 4 MiB 的块，只传云端没有的块。改了一个 100 MB 存档里的一小段，通常只传几 MB |
| **秒传** | 云端已存在相同内容（换机器、重装、回滚）时，一个字节都不用传 |
| **本地块缓存** | 下载过的块缓存在本地，再次下载其他版本时直接复用 |
| **并发 + 断点续传** | 默认 4 线程并发；中断后重来，已传的块自动跳过，从没传的部分继续 |
| **智能忽略** | 默认跳过 `session.lock`、`*.tmp`、`logs/`、`crash-reports/` 等无意义或易变文件，规则可在设置里追加 |

每次同步都会生成一个**版本快照**，可随时回滚；本地与云端同时改了同一个文件时，会弹窗让你逐个选择「用本地 / 用云端 / 都保留」，覆盖前还会自动做**硬链接备份**（几乎不占空间）。

## 六、配置文件

- Windows 客户端：`%LOCALAPPDATA%\MCSync\config.json`（exe 同目录存在 config.json 时为便携模式）
- 存档同步状态：`<存档目录>\.mcsync\state.json`（默认被同步忽略）
- 本地备份：`<实例>\saves\_MCSyncBackups\<存档名>-<时间戳>\`
- 服务端数据：Docker 模式在 `./data`（容器内 `/data`），原生模式在 `/opt/mcsync/data`

## 七、安全机制

部署时自动生成 **16 位随机配对口令** 与 **随机高位端口**，写入 `${INSTALL_DIR}/mcsync.env`（权限 0600）。

四道防线：

| 防线 | 做法 |
|---|---|
| 配对口令 | 16 位（62 字符集，约 95 bit 熵），仅在「客户端配对 / 管理页登录」时出示 |
| 客户端私钥 | 配对成功后，客户端用本地生成的 32 字节密钥对每个请求做 **HMAC-SHA256 签名**；此后口令不再传输，私钥永不上网 |
| 重放防护 | 时间戳窗口 ±300s + 一次性 nonce，签名覆盖 `ts/nonce/METHOD/path/body-sha256`，body 被篡改即失败 |
| 暴力防护 | 同 IP 10 分钟内失败 10 次即锁定 10 分钟；可选 IP 白名单（支持 CIDR） |

另外：启用鉴权时 **关闭 `/api/docs` 与 OpenAPI 结构**，响应统一加 `nosniff` / `DENY` / `no-referrer` / `no-store`，
管理页会话为 HttpOnly + SameSite=Lax Cookie，口令轮换或撤销客户端立即生效。

**客户端怎么用**：设置 → 填「登录账号 + 口令」（管理员在面板创建）→ 自动登录（只需一次）。
之后每次同步都用本机私钥签名，口令不再传输。换机器就再登录一次，互不干扰。

**运维命令**：
```bash
sudo bash deploy.sh --show-token        # 找回管理员密钥
sudo bash deploy.sh --rotate-token      # 换口令（会撤销所有客户端，需重新配对）
sudo bash deploy.sh --revoke-clients    # 撤销全部客户端
sudo bash deploy.sh --allow-ip 1.2.3.4  # 追加 IP 白名单
```

**建议**：公网长期使用时，前面套 Nginx 做 HTTPS 反向代理，并设 `MCSYNC_TRUST_PROXY=1` 让服务端识别真实 IP。

## 八、常见问题

**Q：客户端找不到我的 PCL2 实例？**
PCL2 多为绿色版，位置不固定。点左侧 **➕** 手动选择 PCL 所在文件夹，或在「设置 → 连接」里把目录写进「额外实例目录」，然后把「实例扫描深度」调到 4~5 再扫描。

**Q：客户端报 "too many 503 error responses"，但服务器明明是好的？**
这是系统代理劫持。Clash / v2ray 等会设 `HTTP_PROXY=127.0.0.1:7890` 或 `10808`，
requests 默认会把同步流量也发给代理，代理不稳定就返回 503。
MCSync **默认已绕过系统代理**；若你确实需要走代理，在「设置 → 连接」里打开
「使用系统代理」。

**Q：上传报 "有 N 个数据块上传失败"？**
说明个别块连续 3 轮都没传上去。客户端会自动补传并复查，仍失败才报错。
通常是网络抖动或代理干扰，重试即可；换更稳定的网络或调低并发线程数也有效。

**Q：上传报 409 missing_chunks，且 sample 里是同一个哈希重复出现？**
存档里有 **0 字节空文件**。旧版本会把空文件的"整文件哈希"（xxh128 空内容 = `99aa06d3...`）当成数据块写进清单，
但空文件不产生任何块，云端自然没有 → 409。已修复：空文件不再产生数据块，服务端也不再为它补哈希。

**Q：客户端提示"认证失败 / 该客户端未登记"？**
服务器开了鉴权。在设置里填 16 位口令（`sudo bash deploy.sh --show-token` 查看），
点「重新配对」即可。换过口令或执行过 `--rotate-token` 的，所有客户端都要重新配对。

**Q：客户端每次启动都要扫很久？**
首次启动会做一次全盘扫描，之后直接读取已保存的实例路径（毫秒级），不再遍历磁盘。
想找新实例时点「🔍 全盘重扫」；只是刷新已有实例就点「⟳ 实例重扫」（只扫上次命中的目录，很快）。
已失效的路径会自动剔除。

**Q：服务器地址填了没保存？**
地址栏回车、失焦、点「连接测试」都会立即落盘，退出时也会再存一次，下次启动自动回填。

**Q：脚本打印的端口和实际能连上的不一样？**
新版部署会做三重保障：systemd 单元里 `Environment=` 显式写端口（不依赖 env 文件权限）、
`ExecStart` 带 `--port`、部署完成后**实测探测真实监听端口**并以实际值为准显示。
同时会清掉旧版本残留的服务进程（老服务常占着 8650）。
若仍不一致，脚本会明确提示并给出 `systemctl status` / `journalctl` 排查命令。

**Q：切换主题后界面一半深一半浅？**
已改为切换时**整体重建界面**。程序里大量控件显式指定了颜色，不会跟随
`set_appearance_mode` 自动变化，逐个改色必然有遗漏，重建是最彻底的做法。
重建会保留实例/存档/云端列表与选中项，不影响使用。

**Q：扫描很慢、CPU 和磁盘都没跑满？**
三处优化：`os.scandir` 替代 `listdir + isdir`（省掉逐项 stat）、
跳过 Program Files / node_modules 等无关目录树、多个根目录与多个存档**并行处理**。
首次全盘扫描后结果会缓存，之后启动直接复用，不再遍历磁盘。

**Q：配置文件存在哪？**
系统级应用数据目录，**不是程序所在目录**：
`%LOCALAPPDATA%\MCSync\config.json`（Windows）、`~/.config/MCSync/config.json`（Linux）。
旧版本放在 exe 同目录，升级后会自动迁移过去，不会丢配置。
可用环境变量 `MCSYNC_CONFIG_DIR` 覆盖。

**Q：设置页里配对口令输入框点不到 / 输不进去？**
已修复。旧版本「连接」页里 `row=1` 和 `row=4` 各被两个控件占用，
后放置的控件盖住了口令框，导致点不到也输入不进去。现在每个 grid 行只放一组控件，行号严格递增。

**Q：老存档点「管理」提示私钥验证失败？**
已修复。根因是签名基串里路径的编码形态不一致：客户端按 HTTP 请求行签名（百分号编码，
如 `/api/save/%E6%88%91.../versions`），服务端 ASGI 拿到的是解码后的路径
`/api/save/我的世界存档/versions`，两者 HMAC 不同 → `bad_sign`。
纯英文名的存档不受影响，所以表现为"新上传的能管理、中文名/带空格的老存档不能"。
服务端现在会尝试路径的所有等价形式，老客户端与新客户端都能正常访问。

**Q：开启鉴权后能上传但下载报 401？**
已修复。数据块下载接口漏了签名头（上传接口有、下载接口没有），
自测用关闭鉴权的环境跑，所以这个 bug 一直没暴露。现已补齐。

**Q：云端存档怎么和整合包对应？**
上传时客户端会把当前实例名（整合包名）一起提交，云端按整合包**分组显示**：
「📦 1.20.1-Forge」下挂它自己的存档，「📦 1.12.2-Forge」下挂它自己的。
老存档（没有整合包信息）归入「🗂 未分类」，可点云端面板的「🏷 归类」手动指定归属。

**Q：两个整合包里有同名的存档会混吗？**
不会。同名存档分属不同整合包时，服务端自动另建一条（显示为「MyWorld (1.12.2-Forge)」），
两边各自独立计版本、独立下载，原记录不受影响。

**Q：云端列表为什么不再显示 v1/v2？**
版本号是**单个存档自己**的上传序号，不同存档的 v1 互不相干，并列展示会让人
误以为它们是同一套版本。现在列表主标识改为「整合包 · 存档名 + 更新时间」，
版本号只在点开「版本管理」后以「第 N 版」出现。

**Q：连不上服务器 / 一直超时？**

**客户端始终直连，不走任何代理**——连自己的服务器不需要代理，
系统里装的 Clash / v2ray 反而会把流量劫持走导致失败。

排查顺序：
1. 服务器地址与端口是否正确（部署完会打印，端口是**随机高位端口**）
2. 云服务器**安全组是否放行了该 TCP 端口**（阿里云/腾讯云控制台里加）
3. 服务是否活着：`systemctl status mcsync` / `journalctl -u mcsync -f`
4. 本机防火墙是否拦截

> 需要代理的是 **push.bat 推 GitHub**，那是 git 的事，默认走
> `http://127.0.0.1:10808`。换端口用 `--proxy`，不走代理用 `--no-proxy`，
> 只测代理通不通用 `--check-proxy`。

**Q：连不上服务器？**
先在服务器上看 `bash deploy.sh --status`，再确认端口已放行（`ufw allow 8650/tcp` 或云厂商安全组）。

**Q：同步会不会把存档弄坏？**
覆盖前会自动硬链接备份；每次同步都是新版本，旧版本不会被覆盖，随时可回滚。只有在你明确选择「用云端」时本地才会被覆盖。

**Q：部署完显示的 IP 不对，客户端该怎么填？**
服务器在内网时脚本显示的是局域网 IP，**客户端在另一台机器必须填公网 IP**。
脚本会优先探测公网 IP（云厂商元数据 → 公网回显服务），探测不到会明确提示。
事后可随时用 `sudo bash deploy.sh --status` 再看，或用
`sudo bash deploy.sh --public-ip 1.2.3.4` 手动指定。

**Q：多人共用一台服务器？**
当前是免认证单空间模式（适合家庭 / 小团队可信环境）。需要多人隔离可以给服务端加一层反向代理的 Basic Auth。
